## 2025-02-18 - Internal Error Information Disclosure via Express API boundaries
**Vulnerability:** The application was catching and passing raw `Error` and driver-specific exception objects directly into API error responses via the `sendError` utility. This could leak sensitive database query details, SQL structures, stack traces, and local file paths to client-facing web applications.
**Learning:** These leaks existed because developers used simple generic try/catch handlers that passed the caught exception object straight into the error helper. Standardizing and sanitizing the response payload at the global boundary helper (`sendError`) provides a robust defense-in-depth layer.
**Prevention:** Always implement a strict sanitizer at central API boundaries that strips out non-public details (such as `stack`, `sql`, `query`, or custom database properties) from error objects before transmitting them to clients. Securely log the rich raw details only to secure server-side logging systems.
