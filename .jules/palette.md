## 2025-03-01 - Arabic-First RTL Layout Focus and Navigation Alignment
**Learning:** In Arabic-first RTL (Right-to-Left) POS interfaces, standard keyboard navigation paths (such as `ArrowLeft` and `ArrowRight`) can easily feel counter-intuitive if they are mapped to LTR assumptions. In a true RTL catalog grid, `ArrowRight` should move to the previous item (visually left-wards), while `ArrowLeft` should move to the next item (visually right-wards). Unlabeled icon buttons (such as cart deletions, quantity steps, and toggle states) present a significant accessibility barrier to screen-reader users who rely on screen narration.
**Action:** Always map arrow-key grid navigation in RTL to mirror the visual flow of the text direction. Always provide explicit `aria-label` attributes to any icon-only button and mark decorative icons inside buttons with `aria-hidden="true"`.

## 2026-08-06 - Interactive Search and Share Dialog A11y and Keyboard Enhancements
**Learning:** Interactive search dropdowns and share panels are primary focus areas for screen reader and keyboard-only users. Merely relying on ArrowUp/ArrowDown selection is not accessible for screen readers unless connected via the official WAI-ARIA Combobox / Listbox spec using attributes like `aria-autocomplete="list"`, `aria-controls`, and `aria-activedescendant` mapped to active element IDs. Additionally, when using multiple tabs in dialog panels, implementing standard ARIA `role="tablist"` and `role="tab"` ensures assistive technology correctly narrates the navigation context, coupled with visual `focus-visible` ring indicators that match the active element color theme.
**Action:** Implement exact WAI-ARIA combobox-to-listbox bindings on input and result list wrappers. Ensure all tabs use standard ARIA roles, have explicit focus visible rings, and include Arabic `aria-label` attributes for fully localized accessibility.
